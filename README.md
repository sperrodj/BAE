¡Bienvenido/as a **Bases de Datos**!, el módulo en el que aprenderemos a transformar información desordenada en sistemas capaces de almacenarla, relacionarla y recuperarla de forma segura y eficiente.

Durante el curso no nos limitaremos a memorizar sentencias SQL. Aprenderemos a **pensar como diseñadores de datos**: entender un problema, decidir qué información necesitamos, organizarla correctamente y construir soluciones que puedan crecer sin convertirse en un caos.

---

## 🚀 ¿Por qué estudiar bases de datos?

Casi cualquier aplicación necesita recordar algo:

- una tienda guarda productos, clientes y pedidos;
- una plataforma educativa gestiona matrículas y calificaciones;
- una red social relaciona perfiles, publicaciones y comentarios;
- un videojuego conserva partidas, logros y clasificaciones;
- una aplicación móvil mantiene usuarios, preferencias y actividad.

Sin datos persistentes, muchas aplicaciones olvidarían todo al cerrarse. Y sin un buen diseño, quizá no lo olvidarían... pero encontrarlo sería otra aventura. 🧭

> [!IMPORTANT]
> Una base de datos no es simplemente un lugar donde «guardar cosas». Debe permitir consultar y modificar información manteniendo su **integridad, seguridad y coherencia**.

## 🧭 Nuestro recorrido

| Unidad | Qué aprenderemos | Pregunta clave |
|---|---|---|
| **1. Almacenamiento de la información** | Ficheros, bases de datos, SGBD, modelos, distribución, protección de datos, Big Data y BI | ¿Dónde y cómo conviene guardar los datos? |
| **2. Bases de datos relacionales** | Tablas, tipos de datos, claves, relaciones, restricciones, vistas, usuarios, DDL y DCL | ¿Cómo construimos una base de datos coherente? |
| **3. Realización de consultas** | Consultas simples, filtros, ordenación, agrupamientos, combinaciones, subconsultas y optimización | ¿Cómo obtenemos exactamente la información que necesitamos? |
| **4. Tratamiento de datos** | Inserciones, modificaciones, eliminaciones, guiones, transacciones, bloqueos y concurrencia | ¿Cómo modificamos los datos sin romper nada? |
| **5. Programación de bases de datos** | Funciones, procedimientos, estructuras de control, disparadores, cursores y excepciones | ¿Cómo automatizamos tareas dentro del SGBD? |
| **6. Modelo entidad/relación** | Entidades, atributos, relaciones, cardinalidades, transformación al modelo relacional y normalización | ¿Cómo convertimos un problema real en un modelo de datos? |
| **7. Bases de datos no relacionales** | Modelos documentales, clave-valor, grafos y otras alternativas NoSQL | ¿Qué hacemos cuando las tablas no son la mejor herramienta? |

## 🧠 ¿Qué serás capaz de hacer?

Al terminar el módulo podrás:

- analizar las necesidades de información de una aplicación;
- diseñar modelos entidad/relación y transformarlos en modelos relacionales;
- crear bases de datos con tablas, claves, relaciones y restricciones;
- escribir consultas SQL para obtener información útil;
- insertar, actualizar y eliminar datos de manera controlada;
- utilizar transacciones para proteger la consistencia de la información;
- crear procedimientos, funciones y disparadores;
- gestionar usuarios, permisos y aspectos básicos de seguridad;
- reconocer cuándo conviene utilizar una base de datos no relacional;
- documentar tus decisiones técnicas de forma clara y profesional.

## 🛠️ ¿Cómo trabajaremos?

La asignatura combinará:

- explicaciones breves y ejemplos guiados;
- ejercicios progresivos;
- diseño de modelos y diagramas;
- prácticas con un SGBD real;
- resolución de errores y revisión de consultas;
- pequeños retos basados en situaciones profesionales;
- documentación técnica en **Markdown**;
- uso de **Git y GitHub** para organizar y presentar el trabajo.

La idea es sencilla:

```text
entender el problema → diseñar → implementar → probar → documentar → mejorar
```

Equivocarse forma parte del proceso. Lo importante será aprender a leer los errores, comprobar nuestras suposiciones y justificar las decisiones.

No se trata solo de aprobar una asignatura ni de aprender una lista de comandos. El objetivo es que puedas enfrentarte a los datos de una aplicación y tomar decisiones razonadas:
